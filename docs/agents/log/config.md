- 2026-04-17: `App.cli_config_override_path` caches the `--config-file <path>` override resolved once at `App.init` — BEFORE `run()` calls `sanitizeCurrentDirectory()`. Resolving a relative CLI path via `getCwdAlloc` at save time targets the sanitized cwd (typically `%USERPROFILE%`), which is NOT the cwd `Config.load()` used at launch. Result would be that saves land in a different file than the one CLI-masks the config at runtime. The Settings "Save" path and the Advanced "Open in editor" escape hatch both route through this cached absolute path, guaranteeing they edit the same file that `Config.load` used at launch.
- 2026-04-17: `App.startup_cwd` caches the launch-time cwd (captured in `App.init` before `sanitizeCurrentDirectory()` runs). Both `settingsSaveAndReload` AND the `.reload_config` action wrap `Config.load(alloc)` in a `chdir(startup_cwd) … chdir(cwd_before)` dance so `loadCliArgs` resolves relative `--config-file` argv entries against the SAME cwd the launch used. Without this, a reload after cwd-sanitization resolves `--config-file custom.conf` to `%USERPROFILE%\custom.conf` instead of the file Config.load originally loaded from `X\custom.conf`, silently swapping the runtime config source every time the user reloads. Always restore the sanitized cwd after the reload so downstream code (surface spawn, relative-path lookups) sees the environment it expects.
- 2026-04-17: The `.reload_config` action handler at `win32.zig:~2456` uses the same `defer`-keyed `did_chdir_to_startup` pattern as `settingsSaveAndReload` so cwd restore runs on both the happy path AND the `Config.load` error path. Manual Ctrl+Shift+R reloads that fail on a broken include no longer pin the process to `startup_cwd`.
- 2026-04-16: `apprt.surface.newConfig()` returns a shallow clone; when overriding `Config.command` on that clone, never deinit the inherited command because it is still owned by the source config arena.
- 2026-04-16: Do not add user-facing config knobs for planned-but-unimplemented features. `command-palette-version`, `bell-features.toast`, `accent-follow-system`, `window-titlebar`, `window-scrollbar`, `material`, `material-transient`, `search-bar`, and `notifications` were advisory fields that parsed cleanly but had no runtime consumer — they were silent no-ops and got removed. When a feature ships, add the knob in the same PR as the path that reads it; the default-on / no-flags rollout policy (§12 Q1 of the redesign plan) forbids staged rollouts with config gates. Pure-computation helpers / internal plumbing (like `blendSemanticAccent`) are fine to land as infrastructure; user-facing fields in `Config.zig` are not.
