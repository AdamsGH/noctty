- 2026-10-15: A doc-drift sweep (PKG-63) found that a statement copied from a test is only as true as the options the test runs with. `docs/windows.md` said `ctrl+m`, `ctrl+i`, `ctrl+[` "have no C0 byte" and send `CSI <codepoint>;5u`; the audit's fix kept the CSI u half because `win32/input.zig`'s issue-178 test expects `\x1b[109;5u`. That test runs the default encoder. The shipped path sets `windows_legacy` (`key_encode.zig`, active only while the Kitty flags are 0), where Ctrl+m is CR, Ctrl+i is TAB and Ctrl+[ is ESC (pinned by "legacy: Windows console control table"), and under ConPTY's Win32 input mode the keys are console key records; CSI u is what an application that enables the Kitty protocol gets. Find which `Options` a test passes before quoting its bytes. Other traps: `git merge-base --is-ancestor <commit> <latest tag>` says whether a change is in the latest release but not which release introduced it (caption UIA was in 1.3.131 and first shipped in 1.3.125; use `git tag --contains` and sort -V); the audit's "F6/Shift+F6" was already Ctrl+F6/Ctrl+Shift+F6 since PKG-32; at the time of the sweep the Windows Terminal migration guide mapped `bellStyle` to `bell-features`, which had no runtime consumer; PKG-60 later wired the bell features and audio settings on Windows, so a grep for consumers outside `Config.zig` belongs in any doc that names a setting; `[regex]::Replace(text, pattern, repl, 1)` in PowerShell binds the `1` to `RegexOptions` (IgnoreCase), not a count, which is harmless only while the pattern matches once; and `update-release-copy.ps1` must not blanket-replace the previous version in `why-noctty.html`, whose v1.3.124/v1.3.123 mentions are the verifier contract. `npx prettier` is not installed here; `npx --yes prettier@3.6.2` run from a scratch directory works.
