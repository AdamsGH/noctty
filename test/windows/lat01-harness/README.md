# LAT-01 typing-latency harness (measurement only, not for merge)

Scratch harness from the LAT-01 investigation (typing latency reported on
#299). It is kept on this branch so the numbers in the LAT-01 PR can be
reproduced; the scripts hard-code the investigation's scratch paths and are
not part of the product or of CI.

## What it measures

Keystroke to the first `SwapBuffers` whose frame contains the echoed glyph:

1. `lat-driver2.ps1` copies a built noctty into a new run directory with
   `noctty.portable`, redirects `LOCALAPPDATA`/`APPDATA` there, creates a
   private desktop and starts itself on it. Every child is started with an
   explicit `WinSta0\<desktop>`: a child started with a null `lpDesktop` from
   that driver lands on the Default desktop. The real
   `startup-attempts.json` is checked against the adopted baseline before and
   after each run.
2. noctty runs `lat-echo.exe`, which echoes each byte it reads after a fixed
   delay (a remote shell behind a network round trip). Modes: `vt` (ReadFile
   in VT input mode), `records` (`ReadConsoleInputW`), `ssh` (what
   Win32-OpenSSH's `ReadConsoleForTermEmulModern` does: VT input mode,
   alertable wait, `ReadConsoleInputW`). Styles: `plain` (the byte), `line`
   (a zsh-like coloured line redraw with a suggestion), `tui` (alternate
   screen, input row plus status bar).
3. The driver posts WM_KEYDOWN/WM_KEYUP pairs to the `noctty.win32` child (the
   target's own `TranslateMessage` types the character) at 8-12 keys/s
   (`steady`, holds 50-110 ms) or in bursts of six keys 30-42 ms apart
   (`burst`), QPC-stamping each post, then asks noctty for its trace.
4. `latency_trace.zig` (applied with `apply_trace.py` and `apply_vsync.py`)
   records QPC-stamped events: key messages, pty writes, pty output (with the
   bytes), renderer wakes (with their sources), frame updates, paints and
   swaps. It is inert unless `NOCTTY_LATENCY_TRACE_FILE` is set.
5. `analyze.py` finds each keystroke's echo in the output stream (or, for the
   redrawing styles, the first chunk read after lat-echo wrote it) and the
   first swap whose frame includes it; `aggregate.py` pools runs.

## Emulated display

A hidden desktop is never composed, so `SwapBuffers` returns at once there
(about 0.03 ms on the 240 Hz and the 60 Hz monitor) and an extra present costs
nothing. With `NOCTTY_LAT_VSYNC_HZ=60` the trace patch makes the UI thread
block before `SwapBuffers` the way a vsynced swap chain with one queued frame
does: a present shows at the next vblank, and a second present inside the
same refresh waits for that vblank and shows one refresh later. `display` in
the results is that emulated display time. It is a model, not a measured
display.

`flood-probe.ps1` (generated by `make_flood.py`) is #310's acceptance case: a
50 MB `type`, a jump resize 1.5 s in, and WM_NULL probes every 7 ms.

`results.txt` holds the pooled numbers for every matrix of the investigation.
